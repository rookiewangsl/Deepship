# 代码、训练与运行

最后更新：2026-08-11

## 1. 核心代码

| 文件 | 作用 |
|---|---|
| `src/data/deepship.py` | 扫描、切片、split、读取与 log-Mel |
| `src/data/deepship_metadata.py` | 船名元数据解析、匹配、规范化与验证 |
| `src/models/ma_cnn_a.py` | 当前三分支模型 |
| `src/pipelines/mel_ml/train_deepship_macnna.py` | DataLoader、训练、早停和测试 |
| `src/evaluation/classification.py` | 指标与图表 |
| `scripts/train/train_deepship_macnna.py` | CLI 入口 |
| `scripts/prepare/build_deepship_vessel_manifest.py` | 生成录音到船名组映射 |
| `scripts/check_storage.py` | T7 与数据检查 |

调用链：

```text
CLI → TrainConfig → scan/split → Dataset/DataLoader
→ model + CE + SGD → train/validation → best checkpoint
→ test → metrics/confusion matrix/run config
```

## 2. 当前默认训练参数

| 参数 | 数值 |
|---|---:|
| Batch size | 16 |
| Max epochs | 100 |
| Optimizer | SGD, momentum 0.9 |
| Loss | Cross-entropy |
| Base LR | 1e-2 |
| Warmup | 10 epochs, start factor 0.1 |
| Cosine min LR | 1e-5 |
| Early stopping | patience 10 |
| Seed | 42 |
| Augmentation | None |

旧版 95.15% run 使用固定 `lr=0.01`，没有当前 warmup＋cosine。学习率策略是后续工程调整，
不能在没有公平重训时解释为已验证提升。

## 3. 数据加载与保存

Dataset 每次按 frame offset 从长 WAV 读取 3 秒，在线重采样和计算 Mel。当前
`num_workers=0`；CUDA 时启用 pin memory 和 autocast。

`--cache-root` 只创建预留目录，尚未实现特征缓存读写。

一次完整运行生成：

```text
output_root/
├── models/deepship_macnna_best.pt
├── metrics/deepship_macnna_metrics.json
├── figures/deepship_macnna_{training_curves,confusion_matrix}.png
└── reports/
    ├── deepship_macnna_history.json
    ├── deepship_macnna_run_config.json
    ├── deepship_paper_split_manifest.json
    └── deepship_paper_split_stats.json
```

保存最佳 validation accuracy checkpoint，训练结束后重新加载最佳权重测试，而不是使用最后
一轮。

## 7. 如何判断 run 完整

依次检查：

1. split stats 是否为 14k/4k/2k；
2. run config 的 `num_parameters` 是否为预期版本；
3. history 长度是否覆盖 best epoch；
4. best checkpoint、metrics 和 figures 是否同时存在；
5. confusion matrix 数字是否与 classification report 一致。

当前 Dropbox 旧归档的 `history.json` 只有 43 epoch，但 run config 记录 best epoch 66；完整
76 epoch history 位于 T7 的 `deepship_macnna_paper_3branch`。最终指标可用，Dropbox 的
43 epoch history 不应用于解释最终训练过程。
